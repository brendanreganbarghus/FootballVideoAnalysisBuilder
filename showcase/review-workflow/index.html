Review Canvas in 4 Steps

How an event becomes trusted.

The engine proposes what happened. Copilot checks the video independently. You make the review decision. Tests protect the result.

01 · WATCH

Inspect the Evidence

Review one 30–60 second clip using normal video, tracking, calibration, and match state.

02 · REVIEW

Copilot Decides Independently

Copilot creates a C# proposal from the video. It does not copy the engine’s E# event.

03 · AUTHORIZE

You Make the Decision

Accept, reject, adjust, or add an event only after the evidence supports it.

04 · PROTECT

Verify the Engine

Compare C# with E#, update only general rules when needed, then rerun protected tests.

How Canvas, Copilot & the Repository Connect

The review stays inside the current GitHub Copilot session.

1 · Canvas Sends Context

The selected segment, event, timestamp, evidence scope, and requested mode enter this Copilot conversation.

2 · Copilot Reads the Repo

Copilot uses the current branch’s rules, cached evidence, tests, and review state—not a separate hidden copy.

3 · Football Law Guides Review

Official IFAB law comes through MATCH_LAW_PROFILE; passes, turnovers, and shots follow the project’s analytics definitions.

4 · Results Return to Canvas

The explanation appears in the matching clip or event conversation. Authorized actions update review state and refresh the screen.

Does the Code Need to Change?

The fresh engine comparison decides.

No Change

The engine already produces the accepted event and both fingerprints are current.

Change Required

A supported event is missing or wrong. Implement a reusable football rule—never a timestamp exception.

Keep Separate

Rejecting C# does not confirm E#. An unmatched E# needs its own evidence review.

How Copilot Helps

Evidence, explanation, and safe implementation.

  • Applies IFAB law, then the project’s analytics definitions.
  • Explains what the selected video actually supports.
  • Refuses to invent a touch, player, control state, or referee decision.
  • Records decisions only after your authorization.
  • Checks fresh source and output fingerprints.
  • Changes general rules and reruns tests when required.
