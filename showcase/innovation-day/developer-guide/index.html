Innovation Day developer setup

From a clean clone to an isolated local experiment.

Code comes from Git. Restricted video, approved models and v41 baseline inputs come from the controlled artifact store. Generated segments and AI runs stay on each developer's computer.

Alfheim is internal non-commercial research material. Do not copy it into Git, a pull request, chat, public storage or an anonymous sharing link. Confirm access rights before sharing the OneDrive folder.
Source control

Clone and isolate your work

Start from the Innovation Day integration branch. Use one feature branch per workstream.

git clone git@github.com:brendanreganbarghus/FootballVideoAnalysisBuilder.git
cd FootballVideoAnalysisBuilder
git switch innovation-day-showcase
git switch -c feature/<short-workstream-name>

Pull requests target innovation-day-showcase, never directly target main.

Python environment

Install the application locally

python -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[test,dataset]"

Use Python 3.10-3.13. FFmpeg must be on PATH or supplied by the optional imageio-ffmpeg dependency.

Controlled artifacts

Make the OneDrive files local and verify them

In OneDrive, select the required folders and choose Always keep on this device.

$artifacts = "$env:USERPROFILE\OneDrive - Xebia\Innovationday Artifacts"
& "$artifacts\00-governance\Verify-Artifacts.ps1"

A checksum match proves the copied bytes are identical to the master. It does not grant a licence or prove model quality.

Local paths

Point the app at the extracted panorama

$artifacts = "$env:USERPROFILE\OneDrive - Xebia\Innovationday Artifacts"
$env:FOOTBALL_ALFHEIM_PANO = Join-Path $artifacts "10-master-data\alfheim\pano"
Copy-Item `
  (Join-Path $artifacts "20-approved-models\internal-poc-only\ultralytics-yolo11n\yolo11n.pt") `
  .\yolo11n.pt

This points the app to the extracted raw video files and copies the approved internal-POC YOLO model into the project root. pano.tgz remains an untouched backup archive.

Shared v41 baseline

Restore configuration and regression fixtures

$baseline = Join-Path $artifacts "30-shared-baselines\v41"
New-Item .\benchmarks\alfheim\window-555 -ItemType Directory -Force
Copy-Item "$baseline\alfheim-config\*" .\benchmarks\alfheim\window-555\ -Force

This restores the v41 pitch and team configuration. Then follow 30-shared-baselines\v41\README.md to regenerate the three protected one-minute videos from pano\: 28:45–29:45, 29:45–30:45, and 30:45–31:45. Their compact expected-result fixtures are then copied into the generated folders. Videos are created locally, not copied from OneDrive.

Local execution

Start the Lab and create a segment

python .\scripts\serve-local.py --bind 127.0.0.1 --port 8080
Match Lab http://127.0.0.1:8080/benchmarks/alfheim/window-555/manual-review/?theme=innovation
Validation Lab http://127.0.0.1:8080/benchmarks/alfheim/validation-lab/?theme=innovation

New prepared segments and all AI outputs stay under benchmarks\alfheim\generated\. This directory is ignored by Git.

Team workflow

Develop on assigned segments without leaking blind tests

  • Use assigned development segments for tuning and debugging.
  • Do not inspect locked blind references before the frozen AI run.
  • Export manual annotations deliberately; browser localStorage is not a team backup.
  • Commit code, tests, small configuration examples and documentation only.
  • Never commit video, model weights, caches, generated tracking media or logs.
Quality gate

Test before opening a pull request

python -m pytest -q
git status --short
git diff --check

Explain the assigned scenario, expected event behavior and benchmark result in the pull request. A new feature does not merge when it regresses the protected pass/turnover suite.
