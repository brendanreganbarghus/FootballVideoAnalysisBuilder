Innovation Day developer setup

From a clean clone to an isolated local experiment.

Code comes from Git. Restricted video and approved models come from the controlled artifact store. Generated segments and AI runs stay on each developer's computer; governed review decisions are checksummed in the shared event-review state.

Alfheim is internal non-commercial research material. Do not copy it into Git, a pull request, chat, public storage or an anonymous sharing link. Confirm access rights before sharing the OneDrive folder.
Source control

Clone and isolate your work

Start from the current validated integration branch. Use one feature branch per workstream.

git clone git@github.com:brendanreganbarghus/FootballVideoAnalysisBuilder.git
cd FootballVideoAnalysisBuilder
git switch feature/pass-shot-validation
git switch -c feature/<short-workstream-name>

Pull requests should target the active integration branch agreed by the team, never assume that a stale showcase branch is current.

Python environment

Install the application locally

python -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[test,dataset]"

Use Python 3.10-3.13. FFmpeg must be on PATH or supplied by the optional imageio-ffmpeg dependency.

Controlled artifacts

Make the OneDrive files local and verify them

In OneDrive, select the required folders and choose Always keep on this device.

$artifacts = "$env:USERPROFILE\OneDrive - Xebia\Innovationday Artifacts"
& "$artifacts\00-governance\Verify-Artifacts.ps1"

A checksum match proves the copied bytes are identical to the master. It does not grant a licence or prove model quality.

Governed review state

Use the shared decisions without copying restricted media

$reviewState = Join-Path $artifacts "30-shared-baselines\event-review-state"
Test-Path $reviewState
& "$artifacts\00-governance\Verify-Artifacts.ps1"

The review extension stores decisions, conversations, engine snapshots, source hashes, cached-output hashes, and regression receipts under this directory. Each save updates 00-governance\checksums.sha256. Generated videos remain local and are not copied from OneDrive.

Copilot Canvas workflow

Use Copilot as an independent reviewer, not an engine echo

The app-native Copilot panel keeps the conversation beside the selected video evidence and current review context.

  1. Prepare & run: select an existing 30–60 second segment or prepare a new one, then run the cached AI pipeline.
  2. Inspect evidence: use Normal, Labelled ball, or AI tracking views; seek by frame; enlarge the review when needed.
  3. Review C#: select a Copilot proposal and use Plan mode to explain or Autopilot only when you intend to authorize a recorded action.
  4. Compare afterward: C# proposals and E# engine events are matched only after Copilot finishes its independent construction.
  5. Handle unmatched E#: verify it independently through the clip conversation; rejecting a nearby C# never confirms it.
  6. Publish: the final gate requires every C# decision, current source/output hashes, exact event matching, and protected regressions.

The general Canvas conversation supports the entire prepared clip or the current time ±2 seconds. Event conversations stay attached to the selected proposal so evidence, corrections, and authorization remain traceable.

Team workflow

Develop on assigned segments without leaking blind tests

  • Use assigned development segments for tuning and debugging.
  • Keep Copilot C# proposals independent from rules-engine E# events until comparison.
  • Rejecting a C# proposal never confirms a nearby E# event.
  • Do not inspect locked blind references before the frozen AI run.
  • Manual review labels are evaluation-only and never become inference inputs or timestamp exceptions.
  • Commit code, tests, small configuration examples and documentation only.
  • Never commit video, model weights, caches, generated tracking media or logs.
Quality gate

Test before opening a pull request

python -m pytest -q
git status --short
git diff --check

Explain the assigned scenario, expected event behavior and benchmark result in the pull request. A new feature does not merge when it regresses focused or protected football-event tests.
